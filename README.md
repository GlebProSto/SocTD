# 🐦 SocTD

SocTD — это социальное веб-приложение для управления задачами, созданное на Python и Django. Оно объединяет публикации задач, список дел, дружеские связи, лайки, комментарии, репосты, уведомления, профили и личные сообщения в одном проекте. Я создал его как практику full-stack-разработки на Django, проектирования реляционных баз данных и построения аутентификации. Главный фокус проекта — реализация социальных взаимодействий и понятного интерфейса для работы с задачами.

## 🦄 Функционал

Вот что вы можете делать с SocTD:

* **Регистрация и аутентификация:** Я реализовал регистрацию, вход, выход и защиту страниц с помощью встроенной системы аутентификации Django.
* **Социальные публикации задач:** Пользователи могут публиковать посты до 280 символов, просматривать ленту с постраничной навигацией и отмечать посты как выполненные.
* **Лайки и комментарии:** Я добавил лайки с обновлением количества через AJAX и возможность оставлять комментарии к публикациям.
* **Репосты:** Пользователи могут репостить публикации и просматривать их вместе со своими постами в соответствующем разделе профиля.
* **Профиль пользователя:** Профиль содержит биографию, загруженную фотографию, дату регистрации, статистику публикаций и список дружеских связей.
* **Заявки в друзья:** Пользователи могут искать других участников, отправлять заявки, принимать их или удалять дружеские связи.
* **Уведомления:** Приложение отслеживает заявки в друзья, их принятие, лайки, комментарии и репосты.
* **Счётчики непрочитанного:** Контекстный процессор показывает в навигации количество непрочитанных сообщений и уведомлений.
* **Личные сообщения:** Я создал чат-комнаты с сохранением сообщений, состояниями прочтения, обновлением чата и AJAX-эндпоинтами.
* **Списки задач:** Авторизованные пользователи могут создавать задачи с датой, добавлять к ним подзадачи и отмечать их выполнение.
* **Администрирование Django:** Админка доступна для управления моделями и данными приложения.
* **Адаптивный интерфейс:** Шаблоны используют отдельные CSS-файлы для общей страницы, ленты, чата, профиля, задач, дружеских связей и уведомлений.

### 🎯 Страницы и эндпоинты:

* `/` — открывает социальную ленту.
* `/register/` — создаёт новую учётную запись.
* `/login/` — выполняет вход пользователя.
* `/profile/` — открывает профиль текущего пользователя.
* `/search/` — ищет пользователей и управляет заявками в друзья.
* `/notifications/` — открывает и помечает прочитанными уведомления.
* `/messages/` — показывает все чаты текущего пользователя.
* `/chat/<username>` — открывает личный чат с конкретным пользователем.
* `/tasks/` — показывает списки задач пользователя.
* `/tasks/create` — создаёт новую задачу.
* `/admin/` — открывает интерфейс администрирования Django.
* `/api/messages/send/` — отправляет сообщение методом POST.
* `/api/messages/updates/?username=<username>&after_id=<id>` — получает новые сообщения выбранного чата.

## 👩‍💻 Процесс разработки

Я начал с настройки Django-проекта и определения основных моделей приложения. Я связал пользователей, профили, публикации, дружеские отношения, уведомления, чаты, сообщения, списки задач и подзадачи так, чтобы их связи соответствовали социальным сценариям.

Далее я создал структуру URL-маршрутов и представления для регистрации, профиля, публикаций, поиска пользователей, дружбы, уведомлений и управления задачами. Затем я использовал Django Forms для валидации данных и шаблоны для построения понятных серверных страниц.

После этого я реализовал социальную логику лайков, комментариев, репостов и уведомлений. Для хранения связей я применил отношения many-to-many и проверял дубликаты взаимодействий, чтобы повторное действие отменяло результат или не создавалось дважды.

Потом я разработал личные сообщения и добавил JSON-эндпоинты для отправки и получения сообщений. JavaScript использует Fetch API для обновления интерфейса чата без полной перезагрузки страницы, а сервер помечает полученные сообщения прочитанными.

Для управления задачами я добавил модели `SubTask` и `TaskList`, а процент выполнения вычислил по количеству завершённых подзадач. Я также добавил постраничную навигацию ленты и оптимизировал выборки с помощью `select_related`, `prefetch_related` и предварительной загрузки дружеских связей.

В завершение я написал тесты Django для профилей, публикаций, дружбы, уведомлений, чатов, задач, поиска и перенаправлений. Я использовал миграции для отслеживания структуры базы данных и описал настройки переменных окружения и резервный выбор базы SQLite или PostgreSQL.

## 🚦 Запуск проекта

Чтобы запустить проект в локальном окружении, выполните следующие шаги:

1. Клонируйте репозиторий и перейдите в папку проекта:
```bash
git clone https://github.com/GlebProSto/SocTD.git
cd SocTD
```

2. Создайте и активируйте виртуальное окружение, а затем установите зависимости:
```bash
python -m venv myenv
myenv\Scripts\Activate.ps1
pip install -r requirements.txt
```

3. Создайте файл `.env` в корне проекта. Если `DB_NAME` не указано, Django использует SQLite, иначе можно подключить PostgreSQL:
```env
SECRET_KEY=замените-на-длинный-случайный-секретный-ключ
DEBUG=True
DB_NAME=
DB_USER=postgres
DB_PASS=ваш-пароль
DB_HOST=localhost
DB_PORT=5432
```
Затем примените миграции базы данных:
```bash
python manage.py migrate
```

4. Запустите сервер разработки Django:
```bash
python manage.py runserver
```
Откройте `http://127.0.0.1:8000/` в браузере. Администрирование доступно по адресу `http://127.0.0.1:8000/admin/`.
